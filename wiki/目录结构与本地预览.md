## 本地预览

站点为纯静态文件，**推荐用本地 HTTP 服务器**打开（部分页面用 `fetch` / ES Module，`file://` 直接打开可能被浏览器拦截）：

```bash
# 在项目根目录执行
python3 -m http.server 8000
# 然后浏览器访问
open http://localhost:8000/
```

入口 `index.html` 会自动跳转到 `worldview.html`。查看全量科技树请访问 `tree_full.html`（数据较大，加载稍慢属正常）。

> 若端口被占用，可改用其他端口，例如 `python3 -m http.server 8788 --bind 127.0.0.1`。

## 前端数据加载顺序（易错点）

主页面的数据文件**必须按以下顺序加载**：

```
assets/techs_extra.js  →  techs_extend.js  →  techs_more.js  →  assets/data.js（最后）
```

因为 `data.js` 中的数据集合是在**加载时**由前三个文件拼接求值的。若先加载 `data.js`，最终只得到核心部分，且不会报加载错误，只会在后续查询时返回空值——症状隐蔽，排查成本高。

## 提交门禁

仓库带 `pre-commit` 钩子，提交时自动运行三道校验，任一不过即阻断：

| 校验 | 作用 |
|---|---|
| `tools/check_docs.js` | 正文中写死的语料总数须与真实数据一致 |
| `tools/regen_text.js --check` | 节点文案须与当前依赖网络一致（文案是生成时刻的快照） |
| `tools/audit_net.js --check` | 结构指标不得相对 `audit/baseline.json` 劣化（环 / 自环 / 重复边 / 断链 / 年份倒挂须为 0） |

钩子文件不随仓库版本化，新克隆后需执行 `sh tools/install_git_hooks.sh` 安装。确需跳过时用 `git commit --no-verify`。
